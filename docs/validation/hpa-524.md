## Threshold behavior (automated, domain)

- Weapon switches exactly once at half HP: `dreadnought_switches_weapon_once_at_half_hp` (`src/domain/enemy.rs`) — Graviton at 40 HP, Overload at 20, still Overload at 19. The selection is computed from live HP in `unit_weapon` (`UnitArchetype::Dreadnought if unit.hp * 2 <= unit.stats.max_hp => 1`); there is no stored phase and no registry.
- Committed intent is immutable across the crossing: `crossing_threshold_does_not_rewrite_committed_dreadnought_intent` — the intent committed above half HP stays byte-identical after direct damage drops the boss to 20; only the *next* `build_intent` picks Overload.
- Overload range 2–4 pinned, never self-overlapping: `overload_cross_never_contains_its_attacker` asserts `(min, max) == (2, 4)` and that the attacker's own cell is absent from the committed Cross1 footprint.
- Close-in pressure: `dreadnought_overload_closes_from_range_five` — below threshold the Move-1 planner closes from range 5 into range 4 (inside Overload's band).
- Turnabout via boss friendly fire: `redirected_graviton_completes_turnabout_and_cancels_the_knocked_out_controller` walks the real seed-2 redirection line through the actual `BattleState::attack` Vector Pulse (Vanguard vacates, Interceptor fires Vector Pulse — damage + push — onto the boss's committed footprint `(5,7)`) and pins the event order: boss Graviton roll hits the redirected Controller → `OptionalObjectiveCompleted` → Controller `IntentCanceled`. Vector Pulse's 3 damage (9 → 6) plus the Graviton's 7 damage knocks the Controller out, so it never fires into the vacated cell; the test asserts the KO and the absence of a Controller `AttackHitEmpty`.
- Initiative order: the planner's `initiative()` ranks Dreadnought 40, Controller 35 (`src/domain/enemy.rs`) — the boss resolves before the Controller.
