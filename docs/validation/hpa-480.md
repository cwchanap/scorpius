2026-09-08 on the `hpa-480-ui-visual-parity` worktree. This note covers the
shared canvas, exact-font plumbing, marker ownership, and headless UI picking
seam. Task 3's production battlefield and mesh cutover remain out of scope.

## Headless evidence

The resize proof uses Bevy's real `UiPlugin`, `PickingPlugin`, and
`InteractionPlugin` with the minimum asset/text/input resources they require.
It spawns a real `CanvasRoot` and `Node` stage, lays the stage out through the
UI pipeline, sends a synthetic pointer move through the picking backend at
1920x1080, resizes to 1600x1000, refreshes `UiScale` before the backend, and
verifies that the same authored `GridPos(4, 7)` is recovered from the actual
`HitData.position` and computed stage size in `HoverMap` after the resized
layout settles. The fixture is
`resize_recomputes_scale_before_picking_and_preserves_stage_cell_hits` in
`tests/ui_layout.rs`; it does not start a window, renderer, or `DefaultPlugins`.

The focused camera ownership regression is
`battle_teardown_preserves_unowned_cameras` in `src/app.rs`. It proves that
battle teardown removes the marked `BattleCamera` while preserving an
unowned camera.

## Review-fix round 2

The resize fixture now uses the prescribed 1008x764 authored battle-stage
geometry at `(456, 204)` and points at the center of `GridPos(4, 7)`. It reads
the real UI picking `HitData.position` for `StageProbe`, converts the normalized
node-local hit through the observed `ComputedNode.size` and current `UiScale`,
then calls the production `grid_from_stage_point`. Both the 1920x1080 and
1600x1000 passes assert `GridPos(4, 7)`, so a shifted hit that merely remains
inside the generic stage would fail.
