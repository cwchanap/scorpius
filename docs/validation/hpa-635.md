## Failure/no-op evidence (Step 4)

All from live automated results at `f7664eb`:

1. **Defeat does not progress the campaign.** `defeat_is_rejected_without_state_changes` (`tests/campaign_persistence.rs:50`): `complete_mission` with `victory: false` returns `Err(CampaignError::MissionNotWon)` and `state == before` (bit-equality assert). Defeat UI offers Restart only: `defeat_shows_restart_visible_enabled_and_hides_continue` (`src/presentation/ui.rs:990`).
2. **Invalid Aegis target is a no-op.** `aegis_requires_active_vanguard_and_living_adjacent_ally` (`src/domain/battle.rs:687`): `use_aegis` on a non-adjacent ally returns `Err(InvalidAegisTarget(GUNNER))`, on a dead ally `Err(InvalidAegisTarget(INTERCEPTOR))`, on the wrong pilot `Err(PilotSkillWrongUnit)`; a later valid use still succeeds on the correct adjacent ally, proving the rejected attempts changed nothing.
3. **Unaffordable/maxed purchases are atomic no-ops.** `unaffordable_purchase_is_atomic_noop` (`tests/campaign_persistence.rs:116`) and `maxed_purchase_is_atomic_noop` (`tests/campaign_persistence.rs:131`): `CampaignError` returned, credits/levels bit-identical; `failed_purchase_leaves_disk_and_memory_unchanged` (`tests/campaign_persistence.rs:209`): a failing session-level `persist_purchase` writes nothing to disk and leaves `session.state` unchanged. Failed purchase-**store** coverage (fix commit `f7664eb`): `failed_purchase_store_leaves_memory_unchanged` (`tests/campaign_persistence.rs:230`) — an affordable purchase whose `store()` fails (SaveFile parent path is an ordinary file) returns `Err(FlowError::Save(..))` and leaves `session.state` bit-identical with the original credits/levels.
4. **Failed Continue save leaves Battle/state unchanged.** `continue_victory_save_failure_keeps_battle_and_campaign_state` (`src/presentation/interaction.rs:708`): with a `SaveFile` whose parent path is an ordinary file, `ContinueVictory` leaves pending `NextState` = `None` (screen stays Battle), runtime state stays `MissionId::One` with the original credits, `ActiveMission` stays `One`, and the battle status line contains the save error.
5. **Post-Mission-1 Continue resumes Upgrade.** `title_continue_routes_by_the_saved_next_mission` (`tests/campaign_flow.rs:175`): a save persisted at `next_mission: Two` (400 credits) routes `CampaignUiAction::Continue` to pending `GameScreen::Upgrade`; the same test covers saved `One` → `PreMissionStory`, missing save (no state, "no active campaign"), and corrupt JSON ("corrupted save file").
